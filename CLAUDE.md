# ArthQuest PWA

Offline-first budgeting and savings-quest tracker, installable as a PWA. Frontend is pixel-matched to an uploaded design mockup; business logic is ported from the [arthquest](https://github.com/axarl007/arthquest) Android app's Kotlin domain layer (`App/app/src/main/java/com/arthquest/`). No backend — everything lives in the browser's `localStorage`.

This file is standing context for any session working in this repo. It captures decisions that must be honored across sessions, not a one-time task list — see the repo's GitHub issues for that.

## Source of truth for scope

Work is tracked as GitHub issues, each a tracer-bullet vertical slice with acceptance criteria — **read the issue before starting a ticket**, don't work from memory or a stale summary. Issues declare their blocking edges; respect them.

## Decisions already made — do not re-litigate these

1. **Seed data**: the app starts completely empty (real onboarding, no demo/seeded transactions).
2. **Cartoon icon style**: Twemoji SVGs are bundled locally (`public/icons/twemoji/*.svg`, generated by `scripts/copy-twemoji.mjs`), never CDN-fetched — must work fully offline.
3. **Reminders**: best-effort foreground Notification API only, no push server. Permission is requested only when a user enables a toggle in Settings, never proactively.
4. **App icon**: custom-designed using the app's own quest-progress-ring motif, generated from the live theme tokens (`scripts/gen-icons.mjs` + `scripts/oklch.mjs`) — don't replace with a generic logo.
5. **Deploy**: GitHub Actions → GitHub Pages, triggered on push to `main`. `.github/workflows/deploy.yml` builds+deploys; `.github/workflows/ci.yml` runs lint/test/build on PRs against `main`.
6. **Local data**: plain `localStorage`, no PIN/passcode/encryption — matches the Android app's own unencrypted Room DB. Don't add an app-lock without being asked.
7. **No fake device chrome.** Never render a decorative status bar, bezel, or gesture-nav pill — the real OS/browser supplies that once installed. The *content* (colors, spacing, cards, nav) should still be pixel-identical to the design mockup.
8. **Default theme/icon-style**: Dark + Cartoon. (Android's `AppPreferences.kt` actually defaults to Vibrant+Flat — that's a deliberate divergence, not a bug: the mockup's own default state won for this specific question.)
9. **Deploy URL**: default `github.io` subpath (`https://axarl007.github.io/arthquest-pwa/`), no custom domain. Vite `base` is `/arthquest-pwa/` — see the gotcha below.
10. **Never push to `main` directly.** All work lands on a feature branch, then a PR is opened for the user to review and merge themselves. Don't call `create_branch` targeting `main` — it already exists; a stray call once accidentally fast-forwarded it to a feature commit and briefly fired the deploy workflow before Pages was even enabled. Just push the feature branch and open a normal PR.

## Data model conventions

These mirror the Android app's actual schema/behavior, not the design mockup's demo-script shortcuts (the mockup got some of this wrong — sort order, defaults, stored-vs-derived fields — always verify against the Kotlin source, not the mockup, when the two disagree on *behavior*; the mockup remains authoritative for *visuals*).

- **`state.categories` is one unified array** for both budget categories and quests (`type: 'budget' | 'quest'`), mirroring Android's single `CategoryEntity` table — a Quest is a category row, not a separate collection. Quest-only fields: `questTargetAmount`, `questTargetDate`, `questStatus` (`'active'|'completed'|'redeemed'`), `questRedeemedDate`.
- Every category/income-category gets a **persisted `color`** assigned once at creation via `catColor(index)` (`theme/tokens.js`), continuing the index across however many categories+income-categories already exist. This has no Android schema equivalent — it's design-spec-only. Don't skip it for newly-created categories/quests, or icon tinting regresses to one hardcoded color in Flat icon style (this exact bug shipped once and was caught in review — see `git log --grep=color`).
- **`state.transactions`**: `{ id, type: 'income'|'expense'|'quest_contribution', amount, date (YYYY-MM-DD), createdAt (Date.now(), for stable same-day sort), categoryId, incomeCategoryId, description, isRedemption }`. `categoryId` is the **one** FK for both a budget expense and a quest contribution — there is no separate `questId` field, matching Android's `TransactionEntity`. A redemption transaction is `type: 'expense', categoryId: <questId>, isRedemption: true`.
- **`spent`/`contributed` are never stored** — always derived from `state.transactions` at selector/render time (`domain/transactions.js`: `spentForCategory`, `contributedForQuest`). No such column exists on Android's `CategoryEntity`; don't add one here either.
- **`state.budgetAllocations`**: per-month rows `{ id, categoryId, month: 'YYYY-MM', percentage, amount }`, not a single global percentage. A new month with no rows yet should copy the previous month's forward (`ensureMonthSeeded`), matching `BudgetAllocationRepository.ensureMonthSeeded`.
- Category/quest color in transaction and picker UI follows the design spec's own non-symmetrical rule (see `resolveTransactionSubject()` in `domain/transactions.js`): income/quest-contribution rows use a fixed semantic accent, a redemption row uses fixed gold (`GOLD_COLOR`), only a plain expense row uses its own category's persisted color. Match this pattern for any new UI, don't invent a simpler rule.

## Process

1. Read the GitHub issue for the ticket in full before starting.
2. Read the specific Android Kotlin files the ticket touches — don't guess thresholds/formulas/defaults from the mockup alone.
3. TDD the `src/domain/*` logic layer: write a failing vitest test first, then implement. UI/screen components are verified via a Playwright QA script (`scripts/qa-*.mjs`), not `@testing-library/react` — that split is deliberate, keep following it.
4. `npm test`, `npm run lint`, `npm run build` must all be clean before committing.
5. Run the `code-review` skill on the staged diff before every commit. Fix every finding — review has caught a real bug in every ticket shipped so far. Re-verify after fixing, don't just trust the fix looks right.
6. Commit referencing the ticket (`Closes #N` in the message — inert until merged, that's fine).
7. Push the feature branch, open a PR against `main`, subscribe to its activity.

## Repo structure

```
src/
  domain/     # pure logic, unit-tested with vitest — business rules live here
  theme/      # design tokens (oklch, dark+vibrant), icon system (flat Material Symbols / locally-bundled Twemoji cartoon)
  store/      # localStorage persistence + React context
  components/ # shared UI — CategoryIcon.jsx and sheets/BottomSheet.jsx are the shared primitives, reuse them rather than duplicating icon/sheet markup
  screens/    # one component per screen
scripts/      # build-time asset generation (postinstall) + Playwright visual-QA helpers (not run in CI)
```

## Gotchas

- **Vite `base` is `/arthquest-pwa/`.** Any runtime-constructed absolute path string in JS (not JSX `href`/`src`, which Vite rewrites automatically) needs `import.meta.env.BASE_URL` prefixed — see `theme/icons.js`'s `iconImgUrl()`. Forgetting this 404s once deployed under the Pages subpath even though it works fine in local dev (`base: '/'`).
- `npm install` runs `postinstall` → regenerates `public/pwa-icons/*` and `public/icons/twemoji/*`. Don't hand-edit those generated files; edit the generator scripts instead.
- Chromium for Playwright QA scripts: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome` (path is specific to the sandboxed dev environment).
- Preview a production build with the correct base path: `npm run build && npx vite preview --port 4173`, then hit `http://127.0.0.1:4173/arthquest-pwa/` (note the path suffix).
